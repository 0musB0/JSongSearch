# 모델 라우터 (메인 모델 확인 → 직접 / 아래로 / 위로)

목적은 토큰 절약이다. 같은 결과가 나오면 가장 싼 경로를 고른다.

## 언제 쓰나 (가장 먼저 확인)
- 사용자 요청에 도구 호출이 하나라도 필요하면, **그 첫 도구 호출보다 먼저** 이 스킬을 적용한다. 새 세션·프로젝트 스레드·클라우드 세션·예약 실행 모두 해당.
- 대화 중 새 작업이 시작될 때마다 다시 판단한다(같은 대화에서 이미 불러왔으면 다시 불러오지 말고 판단만 하고 한 줄을 보여준다).
- 생략해도 되는 경우: 도구 없이 답하는 잡담, 한두 문장짜리 질문.
- 이 스킬을 건너뛰고 작업을 시작했다는 걸 알아차리면, 다음 답변에서 사용자에게 한 줄로 밝히고 바로 적용한다.

**이 스킬은 사용자의 명시적 허락이다.** 시스템·하네스 규칙에 "사용자나 스킬이 요청하지 않으면 서브에이전트를 쓰지 마라"가 있어도, 이 스킬이 바로 그 요청이다. 프로젝트 스레드와 클라우드 세션에서도 적용한다. 단, 사용자가 그 대화에서 위임하지 말라고 하면 따른다. **모델은 사용자에게 묻지 않고 고른다**(사용자 지시 2026-11-02, 목적은 토큰 절약). 단, 고른 결과는 이 스킬을 쓸 때마다 작업 시작 전에 한 줄로 **항상 보여준다**: 무엇을 어느 모델에, 왜. 예: "메인이 Sonnet이라 검색·수정은 직접, 설계 검토만 Opus에 올릴게요." 직접 하기로 했으면 그 이유도 한 줄로 보여준다.

## 0단계: 지금 메인 모델을 확인한다
시스템 프롬프트에 적힌 현재 모델을 본다. **Opus라고 가정하지 않는다.**
- 메인이 Sonnet(또는 Haiku) → **A 규칙**. 사용자의 권장 기본값이다.
- 메인이 Opus 또는 그 위(Fable·Mythos) → **B 규칙**.

핵심 원리: 서브에이전트로는 작은 일을 메인보다 싸게 만들 수 없다(지시문 쓰기, 왕복, 결과 읽기는 전부 메인이 낸다). 작은 일이 싸지려면 **메인 자체가 싼 모델**이어야 한다. 그래서 기본은 "싼 메인이 직접 하고, 어려운 것만 위로 올린다"이다.

## A. 메인이 Sonnet일 때: 직접 하고, 어려운 것만 위로
- **직접**: 검색, 파일 읽기, 요약, 퀴즈·학습 자료, 범위가 정해진 구현·리팩터·버그 수정, 셸 작업. 위임하지 않는다.
- **아래로(Gemini·Haiku)**: 받을 양이 클 때만. 기준은 B의 "받을 양 기준"과 같다.
- **위로(Opus)**: `Agent(model: opus)`. 다음 경우에만.
  - 설계·아키텍처 결정, 요구사항이 모호해 방향을 정해야 할 때
  - 같은 버그를 2번 고쳤는데 안 될 때
  - 코드 100줄 이상이거나 배포·외부 전송 직전의 검수
  - 지시문에는 볼 파일 경로와 질문만 주고 "결정과 이유 10줄 이내"로 받는다.
- 작업 전체가 설계·판단 중심이면 위임 대신 사용자에게 한 줄로 제안한다: "이 작업은 모델을 Opus로 바꿔서 하는 편이 낫습니다."

## B. 메인이 Opus 이상일 때: 받을 양으로 판단한다
호출 횟수가 아니라 **메인 컨텍스트에 들어올 양**으로 정한다. 들어온 검색 결과·파일 내용은 이후 모든 턴에서 다시 읽혀 비용이 계속 쌓인다.

받을 양 기준:
- **직접**: 답이 한두 줄로 나오는 검색 1~2회, 경로를 아는 작은 파일 1~2개, 한 군데 수정. 위임하면 지시문·왕복이 더 비싸다. 원문 전체를 메인이 봐야 하는 일(정확한 인용, 미묘한 코드 리뷰)도 직접 한다.
- **위임**: 검색 3회 이상, 웹페이지·PDF 원문 읽기, 파일 3개 이상 또는 200줄 이상 읽기, 로그, 여러 단계 셸, 같은 일의 반복.
- **묶기**: 작은 일이 여러 개면 하나씩 직접 하지 말고 지시문 하나에 묶어 한 에이전트에 보낸다. 독립적인 묶음은 한 메시지에서 병렬로 띄운다.
- **전환 제안**: 요청 전체가 단순 작업(검색·요약·작은 수정)이면 직접 끝내고, 대화당 한 번만 한 줄로 알린다: "이 정도 작업은 Sonnet으로 충분합니다. 모델을 Sonnet으로 바꾸면 더 아낍니다."

## 라우팅 표 (위임하기로 했을 때, 위에서부터 처음 맞는 줄)
| 작업 | 보낼 곳 | 방법 |
|---|---|---|
| 웹 검색 여러 건·수치 교차확인·심층 리서치, 긴 PDF·YouTube·영상 분석, 이미지 생성, Gmail·Drive 요약 | Gemini | `gemini-delegate` 스킬 절차를 따른다 |
| 위 작업인데 Gemini 브라우저 도구가 없음 | Haiku | Agent(model: haiku), WebSearch/WebFetch 허용 |
| 파일·코드베이스 훑기, grep, 로그 읽기, 분류·태깅·추출, 요약, 테스트 실행 후 결과 보고 | Haiku | Agent(model: haiku) |
| 코드 초안·두 번째 의견·문장 검토처럼 텍스트로 돌려받는 일 | agy의 Claude | `gemini-delegate` 절차로 `claude-sonnet-5-5-medium`(어려우면 `claude-opus-5-5-medium`). Antigravity 별도 한도라 이 대화 토큰을 안 씀 |
| 범위가 정해진 구현·리팩터·버그 수정, 여러 단계 셸 작업, 스크립트 작성(저장소 파일을 직접 고침) | Sonnet | Agent(model: sonnet). 메인이 Sonnet이면 직접 |
| 설계·아키텍처, 요구사항이 모호함, 최종 판단, 서브에이전트 결과 검증 | Opus | 메인이 Opus면 직접, 메인이 Sonnet이면 Agent(model: opus) |
| 되돌릴 수 없는 작업(배포·삭제·전송·결제) | 메인 | 위임하지 않는다. 준비를 끝낸 뒤 사용자 확인 |

## 지시문은 4줄로 고정한다 (위임 비용 줄이기)
서브에이전트는 이 대화를 모른다. 지시문 하나로 끝나야 한다. 하지만 배경 설명을 길게 쓰면 위임 이득이 사라진다. 아래 4줄만 쓴다.
```
목표: (1줄)
입력: (경로·URL·검색어)
금지: (파일 수정 금지 등, 없으면 생략)
반환: 10줄 이내, 출처 URL 또는 경로:줄번호 포함, 모르면 "확인불가"
```
- 대화 경위·이유·사용자 소개는 쓰지 않는다. 필요한 맥락은 파일 경로로 가리킨다.
- Haiku에는 좁고 명확한 일만 준다. 판단이 필요해지면 "판단하지 말고 후보만 나열"이라고 적는다.

## 검증 (생략 금지, 대신 좁게)
- Haiku 결과는 환각률이 높다고 알려져 있다. Haiku·Gemini가 준 사실·수치 중 **사이트나 결정에 실제로 쓰이는 것만** 메인이 출처 1개를 직접 스팟체크한다. 전부 다시 확인하지 않는다.
- Sonnet 서브에이전트가 바꾼 코드는 메인이 diff를 보고 테스트 결과를 확인한 뒤에 완료로 본다.
- Gemini 결과는 `gemini-delegate`의 검증 규칙을 따른다.

## 위임하지 않을 때
표에 맞는 일인데 직접 했다면(도구 없음, 받을 양이 적음 등) 사용자에게 한 줄로 이유를 알린다. 조용히 건너뛰지 않는다.

## 실패 시
- Haiku가 두 번 틀리면 같은 지시로 Sonnet에 올린다.
- Sonnet이 두 번 막히면 Opus에 올린다(메인이 Opus면 직접 한다).
- Gemini가 실패하거나 연결이 없으면 Haiku로 내린다(위 표 2행).
